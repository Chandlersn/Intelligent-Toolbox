# 智能收藏箱（Intelligent Toolbox）

> 把你随手收下的东西，攒成一面照见自己的镜子。
>
> 本地优先 · 单进程 · 开箱即用

一个跑在自己电脑上的收藏工具。你把遇到的**仓库、视频、文章**随手丢进来，它替你完成分类、归位、转写与关联——**视频会自动出逐字稿，并整理成结构化笔记**；再把零散收藏**归纳成主题**、**织成一张兴趣图谱**、**画出你的行为画像**。

---

## 为什么做这个

**收藏这个动作，正在变成遗忘的开端。**

每天扑面而来的信息，早就超过了人脑能处理的上限。刷到一条视频、看到一个仓库、读到一篇好文章——第一反应都是「先收藏，回头再看」。但那个「回头」几乎从不发生：收藏夹只会越来越长，越来越不敢打开，你也越来越记不清当初为什么要收。**存下即遗忘**——收藏从工具退化成了心理安慰。

**更麻烦的是，你留下的数据是碎的，而且不归你。**

| 你在哪 | 留下了什么 | 结局 |
|--------|-----------|------|
| 抖音 / B站 | 点赞、收藏、看过的视频 | 平台侧的一条记录 |
| GitHub | star、fork、clone | 平台侧的另一条记录 |
| 稍后读 / 笔记 | 文章、摘录、划线 | 又一个孤岛 |

它们分装在**不同的围墙**里，互不相通，也没法在本地汇总。于是最该发生的关联从未发生——**你摄入的认知，和你产出的作品，从来不碰面。**

**AI 时代，把这件事的分量放大了。** 一边是大模型能总结、能关联、能洞察；另一边是你的数据散在十几个 App 里，取不出来，也聚不起来。结果是一个尴尬的错位：**AI 很强，但它不认识你。**

> 想让 AI 真正帮上忙，前提是你先有一份**属于自己、结构清晰、能被调用**的数据。

**智能收藏箱就是奔着这件事做的：聚合、结构化、本地化。** 不管来源是哪儿都收进同一个地方；自动分类与关联，而不是一堆进得去出不来的原始条目；数据在你手里，才谈得上主权，也才敢放心交给 AI。

---

## 它能帮你做什么

**① 把「存了不看」变成「存了就有用」**
你不用回看，也不用整理。收进来的东西由后台自动分类、归位、建立关联——**收藏不再是终点，而是一次认知网络的节点登记**。你只管收，剩下的交给它。

**② 把碎片聚成一张网，再归纳成主题**
不管你从抖音、GitHub 还是文章里收，都落进**同一张多轴图谱**：按领域、技术栈、用途、动机投影成节点，共同轴上相邻的自动连线。**「探索」页**还把碎片进一步**归纳成主题**——不再是孤立的领域标签，而是「这几个收藏其实在讲同一件事」，并标出每个主题的**缺口**（还差哪类证据），让你看见自己的认知盲点。

**③ 让数据回到你手里，也喂得起 AI**
数据只存本机 SQLite，默认不出本机。一旦结构化了，就能反过来被 AI 调用：接上你自己的 LLM，卡片分析、笔记整理、推荐、画像都会基于**你真实的行为数据**生成——这时候 AI 给出的，才是「只对你成立」的答案。

> 一条底层判断贯穿始终：**行为信号比自述信号更真**。你实际收了什么，比你觉得自己该学什么，更接近事实。

## 两个面，一张图

收藏被分成两侧：

| | 来源 | 留下什么 |
|---|------|---------|
| **生产端** | GitHub / GitLab 仓库 | 仓库卡片：领域、用途、技术栈、成熟度…… |
| **认知端** | 抖音视频、网页 / 文章链接 | **原文逐字稿 / 正文片段** + **结构化笔记** + 萃取卡片，三份都留 |

单看任一面，都只是一份列表。有意思的是把两面放进**同一张多轴图谱**——它们会在共同的主题上相遇。于是你能看见：

> 你摄入的认知，和你产出的作品，中间隔着什么、又在哪里接上了。

这类跨侧的连线会在图谱里被标成**桥接**，一眼可辨。

## 功能

### 收集：多种入口，一次点击

所有入口最终都打向同一个 `/collect`，所以收什么、从哪收都行：

| 入口 | 怎么用 | 适合 |
|------|--------|------|
| **手机 H5**（`/`） | 粘贴链接，可"添加到主屏幕"当 App 用 | 移动端随手收 |
| **跨平台悬浮球**（`ball.js`） | 一个常驻小球，拖文字进去 / 读剪贴板 | 任意页面、任意 webview |
| **书签工具** | 一行 JS，点一下把当前页收进来 | 桌面浏览器 |
| **分享深链** | 把链接拼成 `/collect?url=…&text=…` 发出去，打开即收藏 | 聊天、分享场景 |
| **纯文本投递** | 一整段话丢进来，自动抽出其中的仓库 / 视频 / 网页链接 | 从对话、笔记里捞 |

收藏**同步落库**（毫秒级返回），分析、转写、笔记整理都在后台线程跑，不阻塞你。

### 卡片：自动成卡，可重算、可反馈

每条收藏都会生成一张多维卡片，无需你手动打标签：

| 字段 | 含义 |
|------|------|
| `domain` | 领域（AI·LLM / Web 框架 / DevOps·云 / 数据库……） |
| `purpose` | 一句话用途 |
| `tech_stack` | 技术栈 |
| `why_needed` | 你为什么可能需要它（结合你的备注） |
| `related_nodes` | 与已有收藏的关联 |
| `maturity` | 成熟度（stars 分桶 + 最近提交） |
| `tags` | 多面标签 |
| `recommendation` | 推荐指数 0–5 |
| `source` | `llm` 还是 `heuristic` |

- **来源可分辨**：卡片页会标出这张卡是"AI 分析"还是"规则预览"，不会拿规则结果冒充深度分析。
- **可重算**：内容变了、或你后来配了 LLM，可以对单张卡片一键重算。
- **可反馈**：标"用过 / 弃了 / 还想用"，画像与推荐会参考你的反馈。

### 逐字稿 → 结构化笔记（认知端）

抖音视频和网页文章的收藏，除了萃取卡片，还会留在**原文**和一份**整理好的笔记**：

- **转写**：本地 whisper 出**逐字稿**（离线优先，音频不出本机）。
- **结构化**：逐字稿被整理成 markdown 笔记——`概述` → `核心要点` → `内容纪要（按主题分小节）`，人名、机构、数字、结论都保留。
- **完整、通顺**：**不做字数截断**；逐字稿超长时按句切块再合并，保证篇末内容不丢、结尾不停在半句。
- **长文读得下去**：要点常显、纪要折叠按需展开；标注阅读量（约 N 字 · M 分钟）；右下角**悬浮目录**抽出小节标题，点击直接跳到对应位置，并随滚动高亮当前小节。
- **失败不丢链接**：转写被平台反爬拦住或出错时，收藏照样存下（保留链接与备注），并在卡片上写明原因，不会静默失败。

### 探索页：主题归纳 + 兴趣图谱（同一页分段切换）

「探索」是一个页面，**顶部分段按钮**在「主题」与「图谱」间切换，不另开标签页——既把两件事放在一起看，又不让底部导航拥挤。

**主题归纳（集合级结构）**
- 把库里 N 条条目**归纳**成 M 个主题。它和卡片上的 `domain`（逐条独立的预定义桶）不同：主题是**互相参照归纳**出来的，带成员、覆盖度与缺口，粒度比领域标签更具体（"理财/投资"下可以分出"AI 算力主线的投资逻辑"与"一级市场募资环境"两个主题）。
- **草稿 → 确认**：模型产出先落 `draft` 供你预览，确认后才变 `confirmed`；重算只替换 `draft`，**不抹掉你已经确认的主题**。
- **如实报覆盖率**：归纳覆盖了多少条、还差哪些，页面上一眼可见；覆盖过低会自动再调一次模型取更全的那版。
- 每个主题给出 1–3 条**缺口**：现有条目没能覆盖的关键问题或证据类型，帮你看见认知盲点。

**兴趣图谱**
- 收藏按多轴投影成节点，共同轴上相邻的连成边。
- **缺角**：图谱上的稀疏区域会被标出来，提示你可能想补哪一块。
- **领域相邻**：基于你真实收藏的共现算出，而非预判。
- **跨侧桥接**：生产端与认知端之间的连线单独标色，是"学"与"做"的接线。

### 推荐

- **弱协同推荐**：先由 LLM 依据你的画像推断"你可能还想要什么领域 + 为什么"，再用 GitHub 搜索补上**真实存在**的仓库——只推能落地的，不推空气。
- **本周涨星榜**：GitHub 近一周涨星 Top10，帮你发现当下热度。

### 行为画像

把收藏聚合成一面镜子：领域密度、技术栈分布、活跃时段、来源分布、收藏类型（生产端 ↔ 认知端）比例。

### 更新提醒

对已收藏的仓库做定期比对，星标数、描述、语言有变化时生成**未读事件**，顶部横幅提示、卡片上打角标，不会漏掉你关注的项目在长大。

### 功能模块一览

| 模块 | 位置 | 职责 |
|------|------|------|
| 收集入口 | `web/collect.html` · `web/ball.js` · `web/host.html` · `web/embed.html` | H5 粘贴、悬浮球、书签、分享深链、纯文本投递 —— 统一打向 `/collect` |
| 后台采集 | `src/server.py` | 解析来源 → 转写 → 笔记整理 → 出卡 → 落库 → 同步轴表 |
| 卡片分析 | `src/analyze.py` | 领域/用途/技术栈/成熟度/标签/推荐、关联、画像；规则优先，LLM 可选 |
| 逐字稿转写 | `src/douyin_source.py` | 抖音分享页解析、下载音视频、ffmpeg 抽音频、whisper 转写 |
| 笔记结构化 | `src/analyze.py` | 把口语逐字稿整理成 markdown 笔记（概述/要点/纪要），长文分块不截断 |
| 网页/文章 | `src/web_source.py` | 标准库抓取标题与正文片段（认知端第 4 源） |
| 主题归纳 | `src/topics.py` | 集合级归纳：N 条 → M 个主题（成员/覆盖度/缺口），draft→confirmed 生命周期 |
| 探索页 | `web/explore.html` · `web/topics.html` · `web/map.html` | 主题与图谱同一页内分段切换；跨侧桥接、缺角、领域相邻 |
| 画像 / 推荐 | `web/profile.html` · `web/recommend.html` | 行为聚合；弱协同推荐 |
| 存储 | `src/db.py` | SQLite（WAL）+ 版本化迁移 |
| 配置 | `src/config.py` | 全部可变项集中，`REPO_*` 覆盖，带安全默认值 |

## 快速开始

需要 **Python 3.11+**。核心功能不需要 `pip install`。

```bash
python run.py
```

打开 `http://127.0.0.1:8732` 即可。

| 页面 | 地址 |
|------|------|
| 收集页 | `/`（或 `/collect.html`） |
| 卡片页 | `/cards.html` |
| 探索页（主题 + 图谱） | `/explore.html` |
| 推荐页 | `/recommend.html` |
| 画像页 | `/profile.html` |
| 自检 | `/api/doctor` |

## 配置

全部走环境变量，**都有默认值**，不改也能跑。

### 服务

| 变量 | 默认 | 说明 |
|------|------|------|
| `REPO_PORT` | `8732` | 端口 |
| `REPO_HOST` | `127.0.0.1` | 绑定地址；给手机用改 `0.0.0.0` |
| `REPO_DB` | `<根>/repo_collector.db` | 库路径 |
| `REPO_TOKEN` | 空（关闭） | 设置后所有接口要带口令，对外暴露时用 |
| `REPO_ALLOW_ORIGINS` | 空 | 额外放行哪些主机能发写操作（局域网调试） |
| `REPO_MEDIA_DIR` | `<根>/media` | 认知端音视频落盘目录 |

### 接入 LLM（可选，但强烈建议）

**为什么需要**：默认不配 LLM 也能跑——卡片由内置规则生成（离线、零配置、开箱即用），逐字稿也会退化成按句分段。但规则只看得懂关键词，**接上 LLM，卡片质量、笔记结构、主题归纳都会有质的差别**。

**怎么接**：本工具不内置任何模型厂商，而是复用一个外部的 `llm.py` 模块——这样**密钥不落在本项目里**。

1. 准备一个目录，放进 `llm.py`。它只需要暴露两样东西：`AVAILABLE` 和 `chat()`：

```python
# llm.py —— 放在 REPO_LLM_ROOT 指向的目录
import json, os, urllib.request

AVAILABLE = True
_BASE  = os.environ.get("LLM_BASE_URL", "https://api.openai.com/v1")  # 任何兼容 OpenAI 的服务
_KEY   = os.environ.get("LLM_API_KEY", "")
_MODEL = os.environ.get("LLM_MODEL", "gpt-4o-mini")

def chat(system, user, timeout=20, retries=1, max_tokens=600, use_cache=True):
    body = json.dumps({
        "model": _MODEL,
        "max_tokens": max_tokens,
        "messages": [
            {"role": "system", "content": system},
            {"role": "user", "content": user},
        ],
    }).encode()
    req = urllib.request.Request(
        _BASE.rstrip("/") + "/chat/completions",
        data=body,
        headers={"Content-Type": "application/json",
                 "Authorization": "Bearer " + _KEY},
    )
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return json.load(r)["choices"][0]["message"]["content"]
```

> 用任何 SDK、任何厂商都行，只要 `chat(system, user, ...)` 返回字符串即可。密钥从环境变量读（或写在你自己那侧），**不会进本项目的库、也不会进日志**。
>
> 提醒：`max_tokens` 记得支持外部传入——长笔记（逐字稿结构化）和主题归纳需要更大的上限，写死很小会把输出截断在半句。

2. 启动时把这个目录指给工具：

```bash
REPO_LLM_ROOT=/path/to/your/llm-dir python run.py
```

3. 验证：打开 `/api/doctor`，看 `llm.available` 是否为 `true`。是则卡片与笔记由 AI 生成；不是则自动回退规则，**功能照常**。

| 变量 | 默认 | 说明 |
|------|------|------|
| `REPO_LLM_ROOT` | `D:\测试\lantern-caliper` | 存放 `llm.py` 的目录 |
| `REPO_LLM_TIMEOUT` | `20` | 后台出卡的超时（秒） |
| `REPO_LLM_TIMEOUT_FAST` | `9` | 你在页面点「重算」时的短预算（秒） |

### GitHub Token（可选）

匿名调用 GitHub 的搜索接口限速 **10 次/分**，推荐与涨星榜容易撞限。配一个令牌即可解锁更高额度：

```bash
REPO_GITHUB_TOKEN=ghp_xxxxxxxx python run.py
```

（在 GitHub → Settings → Developer settings → Personal access tokens 生成，只读权限即可。）

### 抖音逐字稿 → 结构化笔记（可选）

默认抖音链接只解析元数据。想真的出**逐字稿 + 结构化笔记**，装两个依赖即可——它们不进仓库，是本机的可选增强，**没装也不影响其他功能**：

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install imageio-ffmpeg faster-whisper
```

- **ffmpeg 免装**：走 `imageio-ffmpeg` 自带的静态二进制，**不需要系统安装 ffmpeg**。解析顺序：项目 `bin/ffmpeg.exe` → `REPO_FFMPEG_BIN` → 系统 `PATH` → imageio-ffmpeg 自带。
- **模型**（约 140MB，已被 `.gitignore` 排除）建议预拉到 `models/faster-whisper-base/`。直连 `huggingface.co` 常被网关拦，用镜像一次拉取：

```bash
mkdir -p models/faster-whisper-base && cd models/faster-whisper-base
for f in config.json tokenizer.json vocabulary.txt model.bin; do
  curl -L --retry 5 -O "https://hf-mirror.com/Systran/faster-whisper-base/resolve/main/$f"
done
```

> 不手动拉也能跑：本地没有模型时会自动从镜像下载（已禁用镜像上会 401 的 Xet 传输后端）。手动拉更稳、也更可控。

装好后 `python run.py` 会自动切到 `.venv`。首次转写较慢，之后离线可用。

| 变量 | 默认 | 说明 |
|------|------|------|
| `REPO_WHISPER_MODEL` | `base` | 模型尺寸，可换 `small` / `medium`（更准更慢） |
| `REPO_FFMPEG_BIN` | 自动 | ffmpeg 路径（一般不用设） |
| `REPO_TRANSCRIPT_MD_MAX_TOKENS` | `4000` | 结构化笔记的输出上限；**调小会把笔记截短** |
| `REPO_TRANSCRIPT_MD_TIMEOUT` | `60` | 笔记结构化的单次预算（秒），后台跑 |
| `REPO_TRANSCRIPT_MD_SINGLE_MAX` | `30000` | 单次能吃下的逐字稿字数上限，超过则按句分块再合并 |

### 对外暴露

要在局域网或公网使用，两件事一起做：

```bash
REPO_HOST=0.0.0.0 REPO_TOKEN=my-secret python run.py
```

`REPO_TOKEN` 一开，所有接口都要带口令；前端把口令放到 `localStorage.repo_token` 即自动随请求带上：

```js
localStorage.setItem('repo_token', 'my-secret');
```

## 技术架构

单进程的本地服务，路由很薄，重活交给后台线程。纯静态前端，没有构建步骤。

```
    浏览器 / 悬浮球 / 分享链接
              │
              ▼
      HTTP 服务（薄路由）────────────▶ 后台采集线程
              │                          │
              │                          ├─ GitHub / GitLab API ──▶ 仓库卡片
              │                          │
              │                          └─ 抖音解析 ─▶ 下载音视频 ─▶ ffmpeg 抽音频
              │                                            └─▶ whisper 逐字稿
              │                                                 └─▶ LLM 结构化笔记
              ▼
       分析层（规则优先，可选 LLM）──▶ 主题归纳 / 图谱 / 画像 / 推荐
              │
              ▼
        SQLite（本地，WAL）
```

| 层 | 位置 | 职责 |
|----|------|------|
| 接入层 | `web/` | 收集 / 卡片 / 探索（主题+图谱）/ 推荐 / 画像 / 分享；跨平台悬浮球 |
| 服务层 | `src/server.py` | 路由、静态分发、业务函数、后台采集线程 |
| 分析层 | `src/analyze.py` | 卡片、笔记结构化、画像、推荐、关联；规则优先，LLM 可选 |
| 归纳层 | `src/topics.py` | 集合级主题归纳（成员/覆盖度/缺口），draft→confirmed 生命周期 |
| 认知端 | `src/douyin_source.py` · `src/web_source.py` | 分享页解析、音视频转写；网页正文抽取 |
| 存储层 | `src/db.py` | SQLite 统一连接（WAL）+ 版本化迁移 |
| 配置层 | `src/config.py` | 全部可变项集中，`REPO_*` 覆盖 |
| 原生壳 | `native-shell/` | 桌面 / Android 工程（骨架） |

**技术选型**：后端只用 Python 标准库（HTTP 服务、SQLite、正则、urllib），**核心零第三方依赖**；前端是原生 JS + CSS，无构建、无框架。可选增强（LLM、转写）全部以「外部模块 / 可选依赖」的形式接入，缺失时自动降级，不拖垮主流程。

**鉴权与安全**：默认只绑回环地址；写操作（删除、重算等敏感动作）有**同源守卫**，只认本机回环来源。对外暴露时开 `REPO_TOKEN`，所有接口校验口令。LLM 密钥放在你自己的 `llm.py` 里，不进本项目。

### 数据模型

```sql
repos (
  id, url, note, status, meta,      -- 地址、备注、状态、平台元数据
  card,                             -- 多维分析卡片（JSON，含结构化笔记）
  kind,                             -- production / cognition
  raw,                              -- 认知端原文逐字稿
  created_at, source
)
-- 多轴模型：以下都是「可从 card 重建的派生物」
axes      (key, name)               -- 轴定义：domain / tech / scene / gap / motive / timeline
repo_axis (repo_id, axis_key, value, weight, source, confidence)
tags      (repo_id, tag)
-- 主题归纳产出（draft→confirmed）
topics        (id, title, summary, gaps, status, origin, signature, created_at, updated_at)
topic_members (topic_id, repo_id)
```

图谱、筛选、画像都建立在这些轴上；卡片一旦重算，轴表随之同步。主题归纳产出自成一张表，重算只替换 `draft`，已确认主题不受影响。

### 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/collect` | 收藏，入参 `{url?, note?, text?, source?}` |
| GET | `/collect?url=&text=` | 分享深链，打开即收藏 |
| GET | `/api/items` | 收藏列表，支持 `?q=` 搜索 |
| GET | `/api/cards` | 卡片筛选 `?domain[]=&tech[]=&motive[]=&use[]=&kind[]=&q=&sort=` |
| GET | `/api/facets` | 筛选面（各轴取值与计数） |
| GET | `/api/graph` | 图谱节点 / 边 / 缺角 / 领域相邻 |
| GET | `/api/topics` | 主题归纳结果（含覆盖率） |
| POST | `/api/topics/rebuild` | 重算主题归纳（低覆盖自动重试，只替换 draft） |
| GET | `/api/profile` | 行为画像聚合 |
| GET | `/api/recommend` | 弱协同推荐 |
| GET | `/api/trending` | GitHub 本周涨星 Top10 |
| GET | `/api/query` | 多轴交叉查询 |
| GET | `/api/updates` | 未读的仓库更新事件 |
| GET | `/api/doctor` | 自检：一致性、LLM 状态、库状态、转写就绪 |
| POST | `/api/card/regenerate` | 重算某张卡片 |
| POST | `/api/item/feedback` | 卡片反馈 |
| POST | `/api/reindex` | 从卡片重建全部多轴数据 |
| POST | `/api/updates/check` | 主动比对 GitHub，产出更新事件 |
| DELETE | `/api/item/<id>` | 删除收藏 |
| GET | `/health` | 健康检查 |

返回均为 JSON，跨源开放。你也可以用自己的脚本、书签工具、快捷指令往 `/collect` 里投：

```bash
curl -X POST http://127.0.0.1:8732/collect \
  -d '{"url":"https://github.com/xxx/yyy","note":"看着有用"}'
```

## 隐私

- 数据只存本机 SQLite，默认只绑 `127.0.0.1`，**不出本机**。
- **音视频与转写全在本地**：下载的音视频只落临时目录、用完即清；转写用本地 whisper，**内容不经过任何第三方**。
- **LLM 密钥不落在本项目**：它在你自己的 `llm.py` 里，不进库、不进日志。
- 只收集你主动投递的链接与备注，不抓取任何其他信息。

## 适合谁 / 不适合谁

**适合**
- 收藏了很多、却从没回看过的人（想把"收藏"变成"用得上"）。
- 想用本地数据喂自己的 AI，而不是把数据交给平台的人。
- 做内容 / 做项目、希望在"学"和"做"之间看见关联的人。

**不适合**
- 想要云端多端实时同步、团队协作的——这是**单机本地优先**工具，没做云端同步。
- 想要现成 SaaS 体验、不愿碰命令行启动的——它需要本地 `python run.py` 起服务。
- 收藏量极小（少于 4 条）时，主题归纳等集合级功能暂不触发（需积累一定样本）。

## 版本迭代

| 迭代 | 内容 |
|------|------|
| 起步 | 收集入口 + 本地落库 + 后台自动成卡 |
| 展开 | 多维卡片、兴趣图谱与缺角、行为画像、弱推荐 |
| 打通 | 分享深链、仓库更新提醒 |
| 多源 | 接入认知端（抖音），生产端 ↔ 认知端 跨侧碰撞 |
| 多源·扩展 | 新增网页 / 文章（认知端第 4 源）：标准库抓标题与正文片段 |
| 收敛 | 页面标题简化、卡片操作区收敛（7 按钮 → 3 + 1）、分享页与画像页重做 |
| **逐字稿落地** | 抖音认知端真正出稿：ffmpeg 免装（imageio-ffmpeg）+ 本地 whisper 模型；转写失败不丢链接、原因可见 |
| **笔记结构化** | 逐字稿自动整理成 markdown 笔记（概述 / 核心要点 / 内容纪要）；**完整不截断**，超长按句分块合并 |
| **长文阅读** | 长笔记减疲劳：要点常显 + 纪要折叠 + 阅读量提示 + **悬浮目录**（点击跳转、滚动高亮） |
| **稳定性** | 轮询不再打断阅读（数据指纹 + 折叠状态记忆 + 滚动保持）；修复 keep-alive 请求体未消费导致的 501 |
| **主题归纳** | 新增 `src/topics.py`：把库里 N 条条目归纳成 M 个主题（成员 / 覆盖度 / 缺口），draft→confirmed 生命周期，低覆盖自动重试；解析层对模型偶发漏写 JSON 闭合做有原则容错 |
| **导航精简** | 主题 + 图谱合并进「探索」页（同一页分段切换），主站工具栏从 7 个 tab 减到 6 个，手机端底部不再拥挤 |

下一步：原生 App——系统分享直达 + 常驻悬浮球，让"随手一收"真正零摩擦。
