# 智能收藏箱（Intelligent Toolbox）

> 把你随手收下的东西，攒成一面照见自己的镜子。
>
> 本地优先 · 单进程 · 开箱即用

---

## 它解决什么问题

我们每天都在做两件事：**消费**（刷视频、读文章）和**生产**（写代码、造东西）。但两边的收藏都躺在各自的书签列表里，存完即弃——没有"为什么收"，也不知道它和别的收藏有什么关系。

这个工具换了个做法：**收藏不是终点，而是一次认知网络的节点登记。**

你点一下就结束，领域、用途、关联全部交给后台。人越懒，数据越全。

> 一条底层判断：**行为信号比自述信号更真**。你实际收了什么，比你"觉得自己该学什么"更接近事实。

---

## 两个面，一张图

收藏被分成两侧：

| | 来源 | 留下什么 |
|---|------|---------|
| **生产端** | GitHub / GitLab 仓库 | 仓库卡片：领域、用途、技术栈、成熟度…… |
| **认知端** | 抖音等短视频链接 | **原文逐字稿** + 萃取卡片，两份都留 |

单看任一面，都只是一份列表。有意思的是把两面放进**同一张多轴图谱**——它们会在共同的主题上相遇。于是你能看见：

> 你摄入的认知，和你产出的作品，中间隔着什么、又在哪里接上了。

这类跨侧的连线会在图谱里被标成**桥接**，一眼可辨。

---

## 它能做什么

- **一键收藏**——网页书签、跨平台悬浮球、手机 H5、分享链接，随手一丢就行。
- **自动成卡**——不用自己分类打标签，后台自动生成领域 / 用途 / 技术栈 / 成熟度。
- **兴趣图谱**——收藏投影成一张图，稀疏处即"缺角"，提示你可能还想补哪块。
- **行为画像**——领域密度、技术栈分布、活跃时段、来源分布，一面照见自己的镜子。
- **弱推荐**——"同类人常收什么"，只提示，不硬推。

### 页面导览

| 页面 | 干嘛的 |
|------|--------|
| 收集页 `/` | 粘贴链接即收，手机可加到主屏幕 |
| 卡片页 `/cards.html` | 所有收藏的多维卡片，可按轴筛选 |
| 图谱页 `/map.html` | 兴趣图谱 · 缺角 · 跨侧桥接 |
| 推荐页 `/recommend.html` | 弱协同推荐 + GitHub 每周涨星 |
| 画像页 `/profile.html` | 你的行为画像 |
| 分享页 `/share.html` | 分享深链，打开即收藏 |

## 上手

需要 Python 3.11+。核心功能不需要 `pip install`。

```bash
python run.py
```

打开 `http://127.0.0.1:8732` 即可。配置项全部走环境变量、都有默认值：

| 变量 | 默认 | 说明 |
|------|------|------|
| `REPO_PORT` | `8732` | 端口 |
| `REPO_HOST` | `127.0.0.1` | 绑定地址；给手机用改 `0.0.0.0` |
| `REPO_DB` | `<根>/repo_collector.db` | 库路径 |
| `REPO_TOKEN` | 空 | 设置后所有接口要带口令（对外暴露时用） |
| `REPO_GITHUB_TOKEN` | 空 | 配了走认证调用，否则搜索接口限速 |
| `REPO_LLM_ROOT` | 见源码 | 复用的本地 LLM 模块；不可用自动回退规则 |
| `REPO_WHISPER_MODEL` | `base` | 逐字稿模型尺寸 |

### 可选：让抖音链接也能出逐字稿

默认抖音只存元数据。想真的转出逐字稿，装上 ffmpeg 和 faster-whisper 即可——**它们不进仓库，是本机的可选增强，没装也不影响其他功能**：

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install faster-whisper
# ffmpeg 放到 bin/ 或系统 PATH
```

装好后 `python run.py` 会自动使用这个环境。首次转写会联网下载模型（约 140MB），之后离线可用。

## 它是怎么工作的

单进程的本地服务，路由很薄，重活交给后台：

```
   浏览器 / 悬浮球 / 分享链接
              │
              ▼
      HTTP 服务（薄路由）──────────▶ 后台采集线程
              │                          │
              │                  GitHub API ／ 抖音解析 + 转写
              ▼                          ▼
        分析层（规则优先，可选 LLM）
              │
              ▼
        SQLite（本地，WAL）
```

前端是纯静态 HTML / CSS / JS，**没有构建步骤**，改完刷新即见。

```
智能收藏箱/
├── run.py          # 一键启动
├── src/            # 后端：配置 / 存储 / 路由 / 分析 / 抖音解析
├── web/            # 前端：收集 · 卡片 · 图谱 · 推荐 · 画像 · 分享
├── tests/          # 单元 + HTTP 集成测试
├── native-shell/   # 桌面 / Android 原生壳（骨架）
└── docs/           # 产品说明与开发计划
```

## 从任何地方投递

所有入口最终都打向同一个端点。所以你也可以用自己的脚本、书签工具、快捷指令往里投：

```bash
curl -X POST http://127.0.0.1:8732/collect \
  -d '{"url":"https://github.com/xxx/yyy","note":"看着有用"}'
```

接口返回 JSON，跨源开放；筛选、图谱、画像、自检等接口都在 `/api/` 下。

---

## 隐私

- 数据只存本机 SQLite，默认只绑 `127.0.0.1`，**不出本机**。
- LLM 的密钥走本地配置文件，不进库、不进日志。
