# 开源仓库收藏工具箱（智能收藏箱）— 产品说明书

版本：v0.2　最后更新：2026-09-11　状态：M0–M8 已完成（M5 为骨架），已做配置层/存储层/一致性契约/测试基线加固

> 本工具是一个**独立产品**，与任何其他知识库 / 认知框架无隶属、无数据互通关系。

---

## 1. 产品定位与愿景

### 1.1 一句话定位
一个**移动优先、跨平台、一键拖入**的开源仓库收藏工具箱：把"收藏"从终态变成你认知网络的一次节点登记，累积之后成为一面客观的"认知镜子"。

### 1.2 要解决的痛点
| 现状 | 痛点 |
|------|------|
| GitHub Star / 通用 agent 装完即弃 | 只存"地址"，不存"为什么收、用在哪里、和别的节点什么关系" |
| 仓库彼此孤立 | 你自己的兴趣画像反而散掉，无法沉淀 |
| 收藏动作重（开页、填表单、分类） | 短视频场景（抖音 / B 站）下尤其错位，发现与收藏割裂 |
| 认知 / 知识层分析空泛 | 行为层的数据（你实际收了什么）信噪比最高，却没被利用 |

### 1.3 核心价值主张
- **收集同步、分析异步**：用户点一下就结束，领域 / 用途 / 关联全部交给后台 agent。人越懒，数据越全。
- **行为信号 > 自述信号**：你用行动投的票，比你"觉得自己该学什么"更真。
- **从收藏反哺认知**：N 个仓库的集合，是你技术轨迹的抽样；图谱上的稀疏区即"缺角"（弱协同推断，绝不硬推）。
- **独立工具，不依附任何框架**：本产品自带完整的"收藏 → 卡片 → 图谱 → 推荐 → 行为画像"闭环，数据自管，不并入任何外部知识库。

---

## 2. 用户场景

| 场景 | 触发 | 入口 | 摩擦 |
|------|------|------|------|
| 短视频发现 | 抖音 / B 站 up 主甩仓库链接，复制 | 移动端 H5 页（可加到主屏幕） | 极低 |
| 任意页面常驻 | 复制链接 / 拖文字到浮球 | 跨平台悬浮球 `ball.js` | 极低 |
| 电脑刷 GitHub | 在仓库页 | 书签工具 / 悬浮球 | 低 |
| 聊天被推荐 | 在对话里贴 URL | 对话捕获（复用现有界面） | 低 |
| 系统分享 / 微信 | 把链接发给机器人 | 分享深链（第二阶段） | 低 |

**设计铁律**：所有入口最终打到同一个平台无关的 `POST /collect` 端点，后端只认 URL（+ 可选的"为什么收"一句备注）。

---

## 3. 核心设计原则
1. **收集同步、分析异步**：点击即落库返回，分析在后台跑，绝不阻塞用户。
2. **脑力卸载**：分类 / 打标签的脑力负担从人身上卸给 agent；"为什么收"保持可选，不逼用户写备注。
3. **移动优先**：主入口是手机 H5，贴合中国短视频发现习惯；桌面书签降为补充。
4. **跨平台悬浮球**：一个常驻元素覆盖任意页面 / webview；web 版即未来原生壳的 webview 内核，不返工。
5. **平台无关后端**：纯 HTTP API + CORS，H5 / 小程序 / 分享深链共用。
6. **本地优先 + 零依赖**：后端用 Python 标准库（http.server + sqlite3），无外部包；UI 纯静态、即时刷新。

## 4. 功能模块

### 4.1 收集入口层（已完成 M0）
- 移动端 H5 收集页 `collect.html`（宣纸墨韵主题，可加到主屏幕）
- 跨平台悬浮球 `ball.js` + 演示页 `ball-demo.html`（拖拽移动、剪贴板读取、拖入收藏）
- 桌面书签工具（嵌于收集页）

### 4.2 收集器后端（已完成 M0）
- `POST /collect`：同步落库 + 去重 + 启后台线程，立即返回
- `GET /api/items`：返回收藏列表（含元数据）
- `GET /health`：健康检查
- 后台 `worker`：拉取 GitHub 仓库元数据（语言 / stars / topics / 描述）

### 4.3 多维分析卡片（M1，本次启动）
- agent 依据元数据 + 用户备注，生成结构化卡片（见第 6 节 schema）
- 字段写入 `card` 列，状态流转 `queued → analyzed(meta) → carded`
- 卡片展示页 `cards.html`

### 4.4 兴趣图谱 / 缺角视图（M2）
- 以"领域 / 技术栈 / 用途"为多轴，把仓库投影成图谱节点
- 稀疏区标注为"可能感兴趣"（弱协同推断），非"缺角"硬结论

### 4.5 弱协同推荐（M3）
- "你收了 A、B，同类人常收 C"式推荐，明确标"可能感兴趣"
- 不因为"没收 X"就硬推 X

### 4.6 分享 / 微信入口（M4）
- 把链接发到机器人即收藏（平台耦合重，第二阶段）

### 4.7 原生壳 / 系统级悬浮球（M5）
- Android `SYSTEM_ALERT_WINDOW` / 桌面 Tauri overlay，内嵌同一 `ball.js`

### 4.8 独立行为画像 / 认知镜像（M6）
- 聚合收藏为个人**行为层**画像（领域密度、技术栈分布、成熟度、行为时间线、活跃时段、缺角），作为一面独立的"认知镜子"；本产品自有的画像能力，与外部知识库无关。

## 5. 数据模型

```sql
repos (
  id         INTEGER PRIMARY KEY,
  url        TEXT UNIQUE,         -- 原始仓库地址
  note       TEXT,                -- 用户可选的"为什么收"
  status     TEXT,                -- queued / carded / pending_meta
  meta       TEXT,                -- GitHub 元数据 JSON（后台拉取）
  card       TEXT,                -- 多维分析卡片 JSON ← 唯一真源
  created_at TEXT,
  source     TEXT                 -- manual/recommend/trend/share/bookmark/ball/import
)
```

**多轴表（M7 起，这些是「可从 card 重建的派生物」）**：

```sql
axes      (key, name)                  -- 维度轴定义：domain/tech/scene/gap/motive/timeline
repo_axis (repo_id, axis_key, value,   -- 仓库在多轴上的同步关联
           weight, source, confidence) -- source: llm / heuristic / user
tags      (repo_id, tag)               -- 轻量标签轴
```

**一致性契约**：`repos.card` 是唯一真源，轴表随时可重建（`python src/migrate.py`），
一致性可自检（`/api/doctor`）。轴表的 `source`/`confidence` 跟随卡片来源，
所以前端能一直分清「AI 分析 / 规则预览 / 用户自述」。

**多维轴（卡片内）**：领域 domain / 用途 purpose / 技术栈 tech_stack / 关联 related_nodes / 成熟度 maturity / 标签 tags。这些是本产品自己的多维分类轴，服务于图谱与画像检索。

---

## 6. 多维分析卡片 Schema（M1）

| 字段 | 含义 | 来源 |
|------|------|------|
| `domain` | 领域，如 Web 框架 / AI·LLM / DevOps | topics+描述+语言 关键词推断 |
| `purpose` | 一句话用途 | 描述提炼 + agent |
| `tech_stack` | 技术栈列表 | language + topics |
| `why_needed` | 你为什么可能需要它 | 用户 note + 启发式/agent |
| `related_nodes` | 可能关联的已有收藏 | 同 domain/tags 的已有仓库 |
| `maturity` | 成熟度分级 | stars 分桶 + pushed_at 新鲜度 |
| `tags` | 多维分面标签 | 用于图谱检索 |
| `recommendation` | 推荐指数 0–5 | 综合成熟度 + 关联度 |
| `source` | 卡片来源 `llm` / `heuristic` | 决定前端标注与轴表置信度 |

**生成策略**：优先 LLM（若配置 key），否则走本地启发式 `analyze.py`，结构一致、可平滑升级。启发式版本保证零依赖可跑。

## 7. 技术架构
- **前端**：纯静态 HTML/CSS/JS，暖纸白 + 暖陶土主题（`--bg/--surface/--ink/--muted/--faint/--line/--accent/--on-ink`），去 emoji、纯文字标签、即时刷新。
- **后端**：Python 3.13 标准库 `http.server` + `sqlite3`，零第三方依赖；`ThreadingHTTPServer` 支持并发；连接统一走 `db.py`（WAL + busy_timeout）。
- **配置**：`config.py` 收口全部可变项，环境变量 `REPO_*` 覆盖，源码里不再有端口/路径硬编码。
- **分析层**：`analyze.py` 本地启发式 + LLM 唯一入口 `_llm_json()`（带超时预算，失败静默降级）。
- **接口**：REST JSON，CORS `*`，平台无关。
- **测试**：`tests/` 零依赖 unittest（单元 + HTTP 集成），含一致性契约回归。

## 8. 接口定义
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/collect` | 入参 `{url?, note?, text?, source?}`，同步返回 `{ok,id,status,dup?}` |
| GET | `/collect?url=&text=&source=` | 分享深链，打开即收藏（移动友好结果页） |
| GET | `/api/items` | 返回 `{items:[{id,url,note,status,meta,card,created_at}]}`，支持 `?q=` |
| GET | `/api/cards` | 卡片筛选（同层 OR / 跨层 AND），支持 `?sort=` |
| GET | `/api/facets` | 分面（domain/tech/motive） |
| GET | `/api/graph` | 图谱节点/边/缺角/领域相邻 |
| GET | `/api/profile` | 行为画像聚合（含来源分布） |
| GET | `/api/recommend` | 弱协同推荐 |
| GET | `/api/trending` | GitHub 本周涨星 Top10 |
| GET | `/api/query` | 多轴交叉查询 |
| GET | `/api/doctor` | 自检（一致性 / LLM / 库 / 配置） |
| POST | `/api/card/regenerate` | 重算某仓库卡片（同时同步轴表） |
| POST | `/api/reindex` | 从卡片重建全部多轴数据 |
| DELETE | `/api/item/<id>` | 删除收藏及其多轴数据 |
| GET | `/health` | `{ok:true}` |

写操作的守卫分工：`/collect` 不限制跨源（书签与悬浮球需要），删除/重算/重建限制同源；配置 `REPO_TOKEN` 后所有接口都要带口令。

## 9. 隐私与安全
- **本地优先**：数据存本机 SQLite，不出本机；默认只绑 `127.0.0.1`。
- **密钥**：LLM key 走灯笼侧配置文件，**不入库、不进日志**；GitHub Token 走 `REPO_GITHUB_TOKEN`。
- **最小收集**：只收仓库 URL + 可选备注，不抓私有信息。
- **写操作守卫**：删除 / 重算 / 重建要求同源（挡「浏览任意网页被偷删收藏」）；`/collect` 必须保持跨源可用，因为书签与悬浮球就是这么用的。
- **对外暴露时**：设 `REPO_TOKEN`（所有接口要口令）+ `REPO_ALLOW_ORIGINS`（放行自己的调试主机）；前端把口令放 `localStorage.repo_token` 即自动随请求带上。

---

## 10. 验收口径（总）
- 一键动作 ≤ 1 次点击 / 1 次拖拽即完成，且不等分析结果。
- 后台分析不打断前台。
- 任意新入口复用同一 `/collect`，零改造。
- UI 严格遵循宣纸墨韵设计语言。
