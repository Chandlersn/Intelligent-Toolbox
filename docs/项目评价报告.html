问题清单 · P0 正确性

这一档直接击穿项目主张，值得当天修。

P0-1
卡片重算后不同步轴表
regenerate 只 UPDATE repos.card，没调 sync_axes()。实测 id=15 卡片说 AI·LLM、轴表说 前端/UI —— 图谱、画像、筛选胶囊、卡片页四处口径互相矛盾。
P0-2
轴表来源标注恒为 heuristic / 0.6
sync_axes 写死来源，不看 card["source"]。实测卡片 source=llm，轴表却记 heuristic。前端费力区分「AI 分析 / 规则预览」，下游把这层信息丢了，confidence 这个卖点不可信。
P0-3
「来自推荐」是恒零指标
推荐页 POST 只带 {url}，后端靠 "来自推荐" in note 判断 —— 全项目无任何写入处。画像页在展示一个永远为 0 的数字，违反「不编假洞察」的自定铁律。
P0-4
推荐依据是被写死的共现表
GAP_COOCCUR 是 10×2 的硬编码字典。缺角是编者预判，不是你的行为统计 —— 与「镜子会自我演化」的主张不符，是理念层最大的断层。

问题清单 · P1 安全与健壮性

P1-1
零鉴权 + CORS 通配 + 不校验 Origin
实测伪造 Origin 仍放行 DELETE。你浏览任意网页时，该页 JS 就能清空收藏或灌垃圾数据。当前只绑 127.0.0.1 挡住外网，挡不住浏览器；一旦改成局域网 IP 就全敞开。
P1-2
SQLite 未开 WAL / busy_timeout
实测 journal_mode=delete。多线程 HTTP + 后台 worker 并发写同一文件，有 database is locked 风险。
P1-3
静态文件靠硬编码白名单、无请求体上限
加一个页面必须改后端；大 body 可打爆内存。

问题清单 · P2 结构与前端

P2-1
LLM 调用与 JSON 解析复制了 4 份
四个 _llm_* 函数各写一遍兜底解析；detect_tags 与 detect_tech_stack 近乎重复。
P2-2
零配置层
8732 散落 20 处；LANTERN_ROOT 直接跨项目 sys.path 注入；GitHub 搜索无 Token 被限速 10/min。README 自己写着「环境变量暂不支持，需改代码」。
P2-3
代码文件双份且已分叉
两份 ball.js（暂无差异，但无同步机制）；两份 host.html 已经不一致。「改一处全壳受益」靠自觉维持。
P2-4
git 仓库零提交
所有文件 untracked，无历史、无回滚、无分支实验能力。
P2-5
文档三处自相矛盾
README 说 M4 待做/M5 待接通，计划表说已全部完成；产品说明书接口只列 4 个（实际 12 个）、数据模型漏了 3 张轴表；两份文档还在讲「宣纸墨韵」，而 theme.css 注释明说不沿用该体系。
P2-6
迁移无版本、DB 不回收
ALTER TABLE + except: pass 吞异常，user_version=0，游离页未 VACUUM。
P2-7
图谱 tooltip 文字实际不可见
color:var(--paper) 而 --paper 本项目从未定义 → var 失效 → 字色回退继承 --ink，底色也是 --ink。#23201B 写在 #23201B 上，只有加粗标题那半行能看见。
P2-8
成熟度映射与文案双错
着色逻辑匹配「常用 / 实验」，实际数据是「顶级 / 成熟 / 活跃 / 新兴」（按 stars 分桶）→ 除顶级外全部涂灰；板块文案还在讲并不存在的实验/常用/核心。
P2-9
设计系统被局部推翻
cards.html 重定义 .pill 为实底并写死 #fff，与 theme.css 的淡底描边冲突；ball.js 颜色全硬编码无变量回退。
P2-10
统计口径失真
后端把技术栈截断到 12 条，前端却拿这个长度当「技术领域」总数；facets 的 tech 轴被 topic 噪声污染 —— 同一条收藏贡献了 5 个近义项各计 1。

优先修法

前五条加起来不到半天，却能修掉全部 P0 与最刺眼的前端事故。

02sync_axes 按 card.source 决定来源与置信度 —— llm→0.85，heuristic→0.6治 P0-2
03推荐页带上 source 字段，画像改读字段而非 grep 中文治 P0-3
04tooltip 换掉未定义变量，用 #FBFAF7 或新增 --on-ink治 P2-7
05成熟度着色改匹配真实取值，板块文案重写治 P2-8
06抽 config.py：端口 / 绑定 / Token / LLM 路径 / GitHub Token 全走环境变量一周内
07抽 db.py：统一连接工厂（WAL + busy_timeout）+ user_version 版本化迁移一周内
08收敛 4 份 LLM 胶水成 _llm_json()，并给它超时与熔断一周内

10补最小 unittest 基线，含「重算后轴表与卡片一致」这条 P0 回归一周内

后续开发方向

近期
1–2 周
  • 巩固地基：上面 12 条全部落地
  • 定义一致性契约：card 是唯一真源，轴表是可重建派生物；提供一键重建 + 差异报告
  • 加自检接口 GET /api/doctor：报告不一致条数、LLM 可用性、限速余量、DB 游离页
中期
1–2 月
  • 接通 M4 / M5（最高优先）：真机分享直达 + 常驻悬浮球。不接通，画像与缺角永远建立在 2 条样本上，再优化也是空转
  • 置信度由样本量算出，而不是模型嘴上说的「高/中/低」
  • 卡片加一个字反馈（用过 / 弃了 / 还想用），把收藏从终点变成轨迹，替掉 stars 分桶这种间接代理
  • 查询下沉到 SQL：给轴建索引，多轴 AND 用 INTERSECT，别再全表拉进内存过滤
远期
方向性
  • event log + 可重放：轴表随时可从事件重建。到这一步，「多维同步存储」才从口号变成能力
  • 多维交叉可视化：图谱现在只投在领域一维上，三轴切换或叠加才是差异化卖点
  • 可分享只读快照：export.json / 静态周报，顺带补上社交闭环
  • 新轴由数据提议：领域白名单不该写死 10 类，样本够了让共现聚类提议、人确认
