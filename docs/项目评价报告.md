## 0. 结论摘要

**这是一副立得住的骨架，但它的立身之本——"多维同步存储与检索"——在代码里还没有闭合。**

| 维度 | 结论 |
|---|---|
| 产品叙事 | 强。"收藏即认知节点登记"、行为信号>自述信号，是真洞察，不是包装。 |
| 架构方向 | 对。`repo_axis(source, confidence)` 这套多轴表，就是"多维"该有的样子。 |
| 完成度 | M0–M3、M6 实跑可用；M4/M5 骨架未接通；M7 表建了、检索没深化。 |
| 致命短板 | **卡片与轴表已经分叉**（实测复现）。声明"同步"，实际两张表各说各话。 |
| 工程化 | 零提交、零测试、零配置层、文档三处互相打架。 |
| 一句话 | 骨架和叙事成立，但"同步"这条契约没被代码和测试钉死之前，它是一组好看的视图，不是产品。 |

综合评分 **3.1 / 5**（分项见 §4）。核心判断：**项目的天花板不在功能数量，而在"轴表 ↔ 卡片的一致性契约"。**

## 2. 项目定位再评估

### 2.1 前提

你在做三件不同的事，它们被压在一个仓库里：

1. **一个采集器**（URL → DB → 元数据）：工具属性，边界清晰，已完成。
2. **一面镜子**（行为画像 / 缺角）：主张属性，价值取决于样本量，目前 2 条样本。
3. **一套多维存储模型**（axes/repo_axis）：基建属性，是 1 和 2 的地基，也是唯一有"创新"嫌疑的部分。

### 2.2 问题

- 1 已经做完了，而且做得不错（收集同步/分析异步、双通道卡片、重算保护、悬浮球组件化复用）。
- 2 的成败不由代码决定，由**入口的摩擦力**决定 —— 而这正好卡在未接通的 M4/M5 上。样本永远是 2 条，画像就是玩具。
- 3 是唯一能沉淀成方法论的东西，但它现在**没有被当成契约对待**：轴表是卡片的派生物，可派生过程没有任何一致性保证（P0-1、P0-2）。

### 2.3 机会

把 3 从"实现细节"提升为"带契约的独立层"：

```
卡片（内容/语义）──▶ 轴表（可检索索引）──▶ 四类视图（卡片页/图谱/画像/推荐）
        ▲                                        │
        └────── 一致性契约 + 可重放（event log）───┘
```

一旦轴表可以被"重放重建"且能自校验，"多维同步"就从一个说法变成一条能做到的承诺。这是这个项目区别于 100 个收藏夹工具的唯一理由。

## 3. 问题清单

### P0 · 正确性与一致性（4 条）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P0-1 | **卡片重算后不同步轴表**。`do_POST /api/card/regenerate` 只 `UPDATE repos.card`，没有调 `sync_axes()`。 | 实测：id=15 `card.domain=AI·LLM`，`repo_axis.domain=前端/UI`（source=heuristic）。 | 卡片页说 AI·LLM，图谱/画像/筛选胶囊说 前端/UI。**四类视图口径互相矛盾**，直接击穿项目主张。 |

### P1 · 安全与健壮性（3 条）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P1-1 | **零鉴权 + CORS `*` + 不校验 Origin**。 | 实测伪造 Origin 仍返回 `Allow-Origin: *`、`Methods` 含 DELETE。 | 你浏览任意网页时，该页 JS 就能对 `127.0.0.1:8732` 发 `DELETE /api/item/<id>` 清空收藏，或灌垃圾数据。当前只绑 127.0.0.1 挡住了外网，挡不住浏览器；一旦照 Android README 改成局域网 IP 就全敞开。 |
| P1-2 | **SQLite 未开 WAL / busy_timeout**。 | 实测 `journal_mode=delete`。 | `ThreadingHTTPServer` 多线程 + 后台 worker 并发写同一 DB，有 `database is locked` 风险（低频但会突然咬一口）。 |
| P1-3 | **无请求体上限；静态文件靠硬编码白名单**。 | `server.py:904` 一长串文件名；实测 `/nope.html`→404。 | 加一个页面必须改后端；大 body 可打爆内存。 |

## 5. 优化建议（按性价比排序）

### 5.1 立刻做（半天，收益最大）

1. **补同步**（治 P0-1）：`regenerate` 分支里 `UPDATE repos SET card=?` 之后加一行 `sync_axes(conn, rid, card, note, meta)` 再 commit。
2. **修来源标注**（治 P0-2）：`sync_axes` 里按 `card.get("source")` 决定 source/confidence —— `llm` → `("llm", 0.85)`，`heuristic` → `("heuristic", 0.6)`；`note` 提炼轴保持 `user, 1.0`。顺手把 `sync_axes` 改成接受显式参数，别让它猜。
3. **修恒零指标**（治 P0-3）：推荐页 `collect()` 的 body 改成 `{url, source:"recommend"}`；后端 `persist_collect` 落一个 `source` 列或在 note 前加标记；`get_profile` 改读字段，别 grep 中文。
4. **修 tooltip**（治 P2-7）：`map.html` 里 `color:var(--paper)` → `color:#FBFAF7`，或更规范地加 `--on-ink:#FBFAF7` 到 `theme.css` 并用变量。
5. **修成熟度映射与文案**（治 P2-8）：`matCls` 改成匹配 `顶级/成熟/活跃/新兴`；板块文案改成"这份东西在你手里的分量：按热度与活跃度分桶"，别再讲实验/常用/核心。

### 5.2 一周内做（结构，一次省掉长期的痛）

6. **抽 `src/config.py`**（治 P2-2）：`PORT` / `HOST` / `LAUNCHER_TOKEN` / `GITHUB_TOKEN` / `LLM_ROOT` 全部 `os.environ.get(k, 默认值)`；前端端口从 `location.origin` 取（现在 cards.html/collect.html/embed.html 里写死了 `127.0.0.1:8732`，其实是 bug 隐患：换端口/换主机就全断）。
7. **抽 `src/db.py`**（治 P1-2、P2-6）：统一 `connect()` 工厂，固定 `PRAGMA journal_mode=WAL; busy_timeout=3000; foreign_keys=ON`；引入 `PRAGMA user_version` 做版本化迁移，把 `ALTER TABLE + except pass` 换掉。
8. **抽 `_llm_json(system, user, expect)`**（治 P2-1）：4 份重复收敛成 1 份，并给 LLM 加**超时 + 熔断**（现在只有 `try/except`，兜得住异常、兜不住 30 秒挂起）。
9. **静态文件改成目录级 serve + 路径穿越校验**（治 P1-3）：`web/` 下任何文件自动可访问，不再维护白名单；同时加请求体大小上限（比如 256KB）。
10. **加一个最小测试基线**（治工程化）：纯 `unittest`，零依赖，覆盖 `valid_repo_url` / `extract_repo_url` / `detect_domain` / `sync_axes` 幂等性 / `get_cards` 的同层 OR 跨层 AND / **以及"重算后轴表与卡片一致"这条 P0 回归**。对零依赖项目，这是最划算的投资。
11. **提交！**（治 P2-4）：`git add -A && git commit`。`.gitignore` 已经把 `*.db`、`.workbuddy/` 排好了，现在一个 commit 都没有是纯风险。
12. **文档收敛**（治 P2-5）：删掉"宣纸墨韵"旧描述（改成暖陶土）；补齐产品说明书的接口与数据模型（或干脆把接口清单只留在 README，避免两处维护）；统一 M4/M5 状态口径。

### 5.3 该做但可以排后面

13. **消除 ball.js 双份**（治 P2-3）：让 tauri 直接引 `../web/ball.js`（或加一个 `sync-ball` 脚本，且 CI/启动时校验 hash 一致）。已在分叉的 `host.html` 同样处理。
14. **技术栈轴归一化**（治 P2-11）：同义词合并（大小写、`-`/`_`、单复数、前缀包含：`dsh` ⊂ `dsh-plugin` ⊂ `dsh-plugin-market` 只留最具体或最泛一个）+ 黑名单（`awesome`/`demo`/`example` 已在 `SOFT_TOPICS`，但那套只作用于 heuristic 通道，LLM 通道返回的 tags 没过滤）。
15. **把缺角从硬编码升级为行为统计**（治 P0-4）：用 `repo_axis` 上真实的领域共现算 lift/支持度，`GAP_COOCCUR` 降级为冷启动种子（样本 < N 时兜底）。这是让"镜子"名实相符的关键一步。

## 6. 后续开发方向

### 近期（1–2 周）· 巩固地基

- 上面 5.1 + 5.2 全部落地；
- 定义并写下**一致性契约**：`repos.card` 是唯一真源，`repo_axis`/`tags` 是可重建派生物；提供一个 `python src/reindex.py` 一键重建 + 校验（等价于现在的 `migrate.py`，但要有幂等与差异报告）；
- 补一条**自检接口** `GET /api/doctor`：报告卡片/轴表不一致条数、LLM 可用性、GitHub 限速余量、DB 体积与游离页。这个接口本身就是"镜子"理念的延伸 —— 项目对自己也照一次。

### 中期（1–2 月）· 兑现产品承诺

- **接通 M4/M5（最高优先）**：真机系统分享直达 + 常驻悬浮球。理由很硬：不接通，"行为画像/缺角/推荐"三页全都建立在 2 条样本上，再优化也是空转。产品价值曲线在这个开关上。
- **样本上量后的可信度机制**：现在 `confidence` 是模型嘴上说的"高/中/低"。改成**由样本量算出来的**（n<10 一律"低"、10–50"中"、>50 且分布显著才"高"），并给缺角加显著性门槛。
- **收藏的"下半场"**：卡片页目前是死档案馆。README 自己也担心这点。建议加一条最轻的动作 —— 每张卡片上"用过/弃了/还想用"的一个字反馈，把收藏从终点变成轨迹（这也直接喂给画像的成熟度轴，替掉 stars 分桶这种间接代理）。
- **查询下沉到 SQL**：`get_cards` 现在是全表拉进内存 + Python 过滤；给 `repo_axis(axis_key, value)` 加索引，多轴 AND 用 `INTERSECT`。现在能跑，但这是"多维检索"该有的样子。

### 远期（方向性）

- **event log + 可重放**：每次卡片/轴变更留一条事件，轴表可随时从事件重放重建。做到这一步，"多维同步存储"才从口号变成能力，也才能支撑"改了分析策略，全部重新推导"而不丢历史。
- **多维交叉可视化**：README 承认"跨轴检索目前是列表筛选，未做图谱化交叉可视化"。图谱页现在只投在 domain 一维上。真正的多维投影（domain × tech × motive 三轴切换或叠加）是差异化卖点。
- **可分享的只读快照**：`export.json` / 静态周报页 —— 把"行为认知镜"做成能给朋友看的东西（这也顺带解决"收藏箱"的社交闭环缺失）。
- **新轴由数据提议**：domain 白名单现在写死 10 类。样本够了以后，用共现聚类提议新轴/新领域，交给人确认。这与"轴定义可扩展（`axes` 表就是为此建的，但目前只有 6 条预置、没人写)"的设计意图才对得上。

## 7. 一句话判断

**这套东西的骨架已经能跑了，叙事也比同类收藏夹高一个维度；但它现在是一组好看的视图，而不是一个产品 —— 差别就在"卡片与轴表的一致性契约"这一条有没有被代码和测试钉死。把 P0 四条修掉（半天的活），再把 M4/M5 接通（让样本从 2 变成 200），这个项目会立刻从"自用原型"变成"能讲给别人听的东西"。**
